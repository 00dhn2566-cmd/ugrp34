## P0 — 사용자가 지금 원하는 것

### 1. 폐루프 오버슈트를 수 cm 로 (진행 중)

**왜**: 사용자 문제제기 "최대속도까지 올라가면 30 cm 오버슈트, 수 cm 로 줄이고 싶다".
문서 실측 근거: 고도 스텝 1 m **22.9 cm**, 1 m 이동(한계 가속) **20.6 cm** (`PERF_STATUS.md:44`).

**⚠ 혼동 주의**: 08-22 에 줄인 0.74 → 0.00 cm 는 **기준 궤적**의 오버슈트다. 사용자가 말한
것은 **드론이 기준을 지나치는 폐루프 오버슈트**로 다른 물건이다 (SESSION §2.5).

**어디까지 했나**: `diagnose/sweep_overshoot_speed.m` 작성·실행. 3 m 직선, 이동시간만 바꿔
피크 속도를 쓸어 `오버슈트 ≈ c·v²` 로 적합하고 목표 cm 별 허용 v 를 역산하게 해뒀다.
중간 결과 (v 0.471 → 0.91 cm, v 0.785 → 2.39 cm) 로 이미 v² 법칙이 잘 맞는다.

**스윕 결과 (완료)**: `오버슈트 ≈ 3.13 · v²` [cm, m/s], 5점 적합 양호.
  v 0.47→0.91 / 0.79→2.39 / 1.18→4.93 / 1.57→8.04 / **1.96→11.55 cm**
  → 5 cm 목표 `v ≤ 1.264` / 3 cm `v ≤ 0.979` / 2 cm `v ≤ 0.800 m/s`
  현 1 kg 공칭 `v=1.2` 는 예상 4.5 cm 로 **이미 수 cm 안**. 사용자가 본 30 cm 는
  agile 프로파일이나 한계 가속 조건일 가능성 — **어느 조건이었는지 확인부터** 할 것.

**다음**: 아래 셋 중 고르기
  (a) **속도 상한을 낮춘다** — 가장 확실. `capability.limits.v` 에 그대로 반영하면 끝.
      대가: 임무 시간. c≈4 이면 5 cm 목표에 v ≈ 1.1 m/s (공칭 1.2 에서 거의 안 깎임)
  (b) **기준을 미리 세운다** — 계획기가 종점을 `overshoot(v)` 만큼 앞당겨 잡는다.
      임무 시간 손해 없음. 다만 종점 정확도가 모델 정확도에 걸림
  (c) **위치 루프 재튜닝** — 근본적이나 골든·회귀 전부 다시. 마지막 수단

**권장**: (a) 로 즉시 스펙에 반영하고, (b) 를 개선안으로 실험.

### 3. 위치 지연 미세 스윕 (10/20/30/40 ms)

**왜**: 자세 여유는 10~20 ms 로 좁혀졌는데 위치는 **0 ms 통과 / 50 ms 실패** 뿐이라 경계를

### 4. C++ 골든 완전 대조

**왜**: 지금은 개연성(스케일비 산포 2.9 → 0.3)만 확인했다. cmd 채널 로그가 없어서다.

**어떻게**: `run_traj_baked.m` 에 `cmd_pitch`/`cmd_roll`/`u_yaw` To Workspace 탭 추가 →
`compare_trace.py` 로 직접 대조. 원래부터 열려 있던 항목.

### 5. ★ `mixYaw` 부호 검정

**왜**: C++ `mixYaw={-1,+1,-1,+1}` × `mixDir={+1,-1,-1,+1}` 로 계산하면 반토크 1차항이
상쇄돼 `τ_max = 0` 이 나온다. 실제로는 0.317 N·m 여야 0.3 N·m 포화 실측과 맞는다.
08-18 골든 확정은 x/y 런의 **roll/pitch 상관**이라 yaw 열은 검정된 적이 없다.

**어떻게**: yaw 스텝 런에서 각가속도 ↔ 모터 차동 최소제곱 상관 (roll/pitch 때와 같은 방법).
`diagnose/probe_prop_and_mixer.m` 의 P2 절차를 yaw 축으로.

## P2 — 미완 기능

### 6. 쉐이퍼 `smooth_stop` 재작업

**왜**: 오버슈트 −56.8 %, 정착 3배 개선인데 **목표 근처에서 저크 밴드를 깬다**
(killer_step j 39, 회귀 5건). 지금은 기본 꺼짐.

**증상 위치**: 목표를 지난 뒤 `g<=0` 구간과 뱅뱅 백스톱의 상호작용. 속도 상한 항을
저크 밴드로 클립해도 남았다 (여러 방식 시도했고 전부 실패 — `traj_shaping.py` docstring 참조).

**제안**: 탐욕적 위치 추종 구조 자체가 한계일 수 있다. 계획기가 이미 4제약을 지키므로
(FINDINGS §5), 쉐이퍼는 **저크 안전 포락선**으로 두고 이 기능은 접는 것도 선택지.

### 7. 속도 조속기 채택 여부

**왜**: 설계·구현·검증 다 했는데 **효과가 0** 이다 (`wrap_aw` 와 결과 완전 동일). 위치가
애초에 안 흔들려서 감속할 이유가 없었다. 평시 손해는 0 % 라 켜도 무해하지만 복잡도만 는다.

**제안**: 코드·문서는 남기고 **채택 보류**. 위치가 흔들리는 조건(더 강한 외란, 실기)이
나오면 그때 재평가.
