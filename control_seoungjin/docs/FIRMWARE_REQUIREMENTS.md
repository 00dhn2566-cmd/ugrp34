# 펌웨어 요구사항 (실기 이식 전 단계)

작성 2026-08-26. 대상: **나중에 펌웨어를 설계·구현할 사람.**

## 이 문서의 범위

**요구사항만 적는다. 설계는 안 한다.** 어떤 MCU를 쓸지, RTOS를 무엇으로 할지,
드라이버를 어떻게 짤지는 여기서 정하지 않는다 — 그건 맡는 사람이 정한다.

여기 있는 것은 **"무엇을 만족해야 하는가"와 그 근거**다. 근거는 전부 이 저장소의
실측이다 (숫자마다 출처를 달았다). 임의로 완화하면 그 실측이 무효가 되므로, 못
지킬 항목이 나오면 완화가 아니라 **재측정**을 요청할 것.

## 1. 타이밍 요구 — 여기가 이 문서의 핵심

### 1.1 자세 루프

| 항목 | 요구 | 근거 |
|---|---|---|
| 주기 | **1 ms 고정 (1 kHz)** | 게인이 1 kHz 후방차분 기준으로 튜닝됨. `filtDAtt = 2500` 은 시정수 **0.4 ms** 짜리 미분 필터라 그보다 느린 주기로는 표현 자체가 안 된다 |
| 주기 지터 | 요구 미정 — **측정해서 보고할 것** | 아래 4.2 |
| **경로 총 지연** (IMU 샘플 → 모터 명령) | **≤ 12 ms 권장 / 16 ms 절대 상한** | `capability.py::LAT_ATT_CLEAN_S / LAT_ATT_MAX_S`. 실측: 12 ms 호버 RMS 0.004°, **16 ms 에서 0.211°, 20 ms 에서 2.44°** (`figure/11_delay/fig_att_gate.png`) |
| 초과 시 | **임무 거부** (감쇄로 못 살린다) | 자세 지연은 감쇄 축이 아니라 **관문**이다 — INTERFACE_SPEC §5c |

이 예산은 **평균이 아니라 최악**으로 판정한다. 평균 8 ms 인데 가끔 20 ms 튀는 구성은
불합격이다 (그 프레임에서 기체가 무너진다).

### 1.2 위치 루프

| 항목 | 요구 | 근거 |
|---|---|---|
| 주기 | **10 ms (100 Hz)** | 관례. 이보다 느리면 자세 명령 계단이 자세 루프를 자극한다 (미검증 — 4.3) |
| **경로 총 지연** (카메라 노출 → 위치 명령 반영) | **≤ 30 ms 강력 권장** | 30 → 40 ms 사이가 **절벽**이다. 돌풍표가 30 ms 까지 배율 1.00 인데 40 ms 에서 **0.55** 로 떨어진다 (`capability.py::_LAT_POS_ANCHORS_GUST`) |
| 40 ms 이상일 때 | 감쇄로 살릴 수 있다 (관문 아님) | 08-23 실측: τ=40 전속은 복귀 12.9 s(실패), s=0.55 면 1.14 s(통과) |
| 60 ms 이상일 때 | **감쇄로도 못 고치는 손상이 있다** | 아래 1.3 |

**절벽이 30~40 ms 사이에 있다는 것이 이 문서에서 제일 중요한 숫자다.** 30 Hz 카메라는
샘플링만으로 평균 17 / 최악 33 ms 를 먹으므로, 프레임레이트 선택이 곧 이 예산을 정한다.

### 1.3 감쇄로 못 고치는 두 축 (2026-08-26 실측, 미해결)

위치 경로 지연이 커지면 **스펙 감쇄로 닿지 않는** 손상이 나온다. 감쇄 `s` 는 기준
궤적의 시간축을 늘리는 조작이고, 아래 둘은 폐루프의 성질이라 지연이 그대로면 동특성도
그대로다.

| 손상 | 무지연 | 60 ms | 80 ms | 감쇄 효과 |
|---|---|---|---|---|
| 고도 한계사이클 (p-p, ~2.5 Hz) | 0.15 cm | 4.7~5.8 cm | **11.0 cm** | 없음 — 80 ms 에서 s=1.00 이 11.01, s=0.37 이 11.09 cm |
| yaw 표류 (외란 후 최대) | 1.13° | **23.78°** | 미측정 | 미측정 |

- yaw 24° 는 **창문 통과 임무를 실패시킨다** (반FOV 이탈). 원인 추정: roll 진동
  ±8° → 믹서 반토크 불균형 → yaw 결합, 그런데 yaw 는 권한이 가장 약하다
  (`limYaw = 20` vs `limAtt = 800`).
- 두 축 모두 **외란이 없어도 t=0 부터 나타난다** — 지연 단독으로 생기는 상시 진동이다.
- 그림: `figure/13_worstcase/fig_worst_altitude.png`, `figure/14_disturbance/`

**요구**: 위 두 축을 **관문으로 다룰지 여부는 아직 미결정**이다. 펌웨어 쪽에서는
"위치 지연이 60 ms 를 넘으면 그 임무는 못 난다"고 보수적으로 가정하고 시작할 것.

## 2. 구조 요구

### 2.1 두 층 분리 — 자세는 전담·상주

```
[전담 코어 / MCU]  자세 + 모터,  1 kHz,  상주, 절대 양보 안 함
        ^ cmdPitch / cmdRoll  (단방향)
[범용 코어]        위치 + 궤적,  100 Hz
[범용 코어]        계획 / 재계획,  best-effort (5~20 Hz)
```

- **단방향 비동기여야 한다.** 자세는 위치를 기다리면 안 되고, 위치도 자세를 기다리면
  안 된다. 한쪽이 늦어도 다른 쪽은 자기 주기를 지킨다.
- 자세 루프가 매 스텝 하는 일은 **PID 몇 개 + 믹서**로 수십 µs 다. **성능 좋은 코어가
  필요 없다 — 필요한 것은 결정론이다.** 느리고 단순한 코어가 오히려 꼬리 지연이 짧다.

### 2.2 물리 분리를 권장한다 (한 SoC 코어 격리보다)

| | 한 SoC 코어 격리 | 물리 분리 (MCU + 컴패니언) |
|---|---|---|
| 꼬리 지연 | 커널 인터럽트·메모리 대역폭 경합·캐시 오염이 남음 | 완전 격리 |
| 컴패니언이 죽으면 | **같이 추락** | FC 는 계속 난다 |

두 번째 줄이 결정적이다. [§9 비상 규약](../INTERFACE_SPEC.md)의 "하트비트 단절 시 래치
강하"는 **자세 제어가 살아 있다는 전제** 위에 서 있다. 한 SoC 에 다 넣으면 커널 패닉
하나로 그 전제가 깨진다.

### 2.3 경계 규약

- 경계 신호는 **`cmdPitch` / `cmdRoll` (rad)** 하나뿐이다. `qc_step()` 안에서 위치
  체인이 만들고 자세 체인이 받는 지점이 그대로 두 코어의 경계가 된다.
- **주기를 놓쳐도 멈추지 않는다**: 위치 코어가 슬롯을 놓치면 자세는 **마지막 명령을
  래치**하고 계속 돈다. 그리고 그 명령이 얼마나 낡았는지를 `measAgeS` 로 보고한다.
- yaw / 고도 기준도 같은 규칙을 따른다.

## 3. 제어기 이식 요구 (`controller_cpp/`)

이미 이식을 전제로 쓰인 코드다. 다음을 지키면 그대로 올라간다.

### 3.1 지켜야 할 것

| 항목 | 요구 |
|---|---|
| **자세 게인 음수** | 의도다 (플랜트 이득 b 가 음수). "부호 수정" 하면 즉시 발산한다 |
| **앵커 불변** | `QcConfig` 의 `*Ref` 값(`kThrustRef 9.79`, `kDragRef 0.597`, `droneMassRef 1.2726`, `pkgSizeRef 0.14³`)은 튜닝 당시 값이다. 갱신 금지 |
| **힙 금지** | `qc_controller.hpp` 는 비행 크리티컬 루프다. 동적 할당·예외·RTTI 없이 돌아야 한다. IO 계층(`qc_io`)만 `std::string`/`vector` 허용 |
| **제어 루프에 IO 금지** | 궤적은 이륙 전 로드, 상태 기록은 별 스레드/저주기 |
| **PID 이산화** | 후방차분, **고정 스텝**. 가변 스텝 금지 |
| **anti-windup** | yaw 만 켠다 (`yawAntiWindup`). 나머지는 원본과 같게 유지 — 골든 대조가 성립해야 한다 |
| **qc_phys 동기화** | `parameters.m` ↔ `qc_controller.hpp` ↔ `gazebo/worlds/gen_worlds.py` 세 곳의 1:1 사본이다. 한쪽을 바꾸면 셋 다 |

### 3.2 주기를 바꾸면 재튜닝이다

게인은 **1 kHz 기준**이다. 자세 주기를 낮추면 `filtDAtt = 2500`(시정수 0.4 ms)이
의미를 잃는다. 주기 변경은 게인 재선정을 부르고, 그러면 이 저장소의 모든 실측이
무효가 된다. **주기를 바꾸려면 먼저 상의할 것.**

### 3.3 미해결 — 이식 전에 닫아야 하는 것

- **`mixYaw` 가 yaw 토크를 못 만든다.** 헤더의 `mixYaw = {-1,+1,-1,+1}` 이
  `mixDir = {+1,-1,-1,+1}` 과 **직교**라 반토크 차동이 상쇄된다 (yaw 권한이 원리적으로
  0). 08-18 골든 실측표는 `mixYaw = -mixDir` 로 정렬된다. Gazebo 하네스는 실측표를
  기본으로 쓰지만 **헤더는 아직 안 고쳤다** (골든 재대조가 선행이라). 실기에 올리기
  전에 반드시 확정할 것.
- **모터 채널 골든 트레이스 재대조.** 2026-08-26 고도 클램프 배선 정정으로
  `motorRef`/`motorCmd` 가 바뀌었다 (위치 체인은 불변).
- **로터 인덱스 → 기하 매핑**이 아직 미확정이다. 모멘트 암도 기하값 0.1125 m 와 골든
  실측 유효값 0.0930 m 로 갈려 있다.

## 4. 관측·보고 요구 (상위 계약)

펌웨어가 **생산해야 하는** 값들이다. 이게 없으면 상위 계획층이 아무 판단도 못 한다.

### 4.1 지금 제일 급한 것 — `measAgeS`

**상태 타임스탬프의 나이 [s].** VIO 출력에 찍힌 시각과 제어기가 그 값을 쓴 시각의 차.
`QcInput.measAgeS` 로 들어가고 `LatencyTracker` 가 자동으로 추적한다. **소비 쪽은 이미
다 배선돼 있고 생산자만 없다.**

이 숫자 하나가 결정하는 것:
- 우리 기체가 30 ms 인지 40 ms 인지 (= 감쇄가 필요한지 아닌지)
- 카메라를 바꿔야 하는지, CPU 를 바꿔야 하는지, 아무것도 안 해도 되는지

**하드웨어를 고르기 전에 이걸 먼저 잰다.**

### 4.2 지터 보고

주기 지터의 **최악값**을 기록해 보고할 것 (평균 아님). 관문이 최악으로 판정되기
때문이다. 자세 루프의 "이 기체는 N ms 다"라고 말할 수 있으려면 꼬리가 짧아야 한다.

### 4.3 나머지

| 값 | 어디로 | 비고 |
|---|---|---|
| `rho` (권한 점유율) | `capability.json` | `max(|u_yaw|/limYaw, |u_att|/limAtt)`, 구간 **최대**로 |
| 모터 속도 4채널 | `current_state.json` | 진단·추정기용 |
| 자세 roll/pitch/**yaw** | 로그 | yaw 표류(1.3)가 새 감시 대상이 됐다 |
| **배터리 잔량** | `EnergyBudget.remaining_wh` | **BMS 또는 전압+전류 전력 모듈에서.** 모터 회전량 적분으로 대체하지 말 것 — 드리프트·노화·온도를 못 보는 열린 루프다 (INTERFACE_SPEC §5e) |

## 5. 안전·페일세이프 요구

- **하트비트 단절 시 래치 강하** (§9 비상 규약). 컴패니언이 죽어도 자세 루프는 살아서
  안전하게 내려앉아야 한다. 2.2 의 물리 분리 권장 근거가 이것이다.
- **모터 명령 클램프**는 제어기 안에 이미 있다 (`limMot = 0.25`). 펌웨어에서 별도로
  한 겹 더 두되, 제어기 클램프를 완화하지는 말 것.
- **입력 계약**: 이 제어기는 **스무더+게이트를 통과한 궤적**을 전제한다. 날것 스텝을
  주면 원본도 릴레이 한계사이클로 왕복한다 (구조 한계, 게인 문제 아님). 펌웨어가
  자체적으로 목표점을 만들어 넣는 경로를 두지 말 것.

## 7. 넘기는 사람이 알아야 할 결정 대기 항목

1. **자세/위치를 물리 분리할지, 한 SoC 코어 격리로 갈지** — 2.2 는 권고이지 결정이 아님
2. **위치 루프를 MCU 에 둘지 컴패니언에 둘지** — 10 ms 주기를 어디서 보장할 것인가
3. **1.3 의 두 축(고도 한계사이클 / yaw 표류)을 관문으로 승격할지**
4. **주기를 놓쳤을 때의 래치 유효시간** — 얼마나 낡은 명령까지 쓸 것인가
5. PX4 전환 시 이 문서의 대부분이 무효가 된다 (그쪽 스케줄러·믹서를 쓰게 됨).
   전환 트리거는 [HANDOFF_EMERGENCY.md](HANDOFF_EMERGENCY.md) 참조
