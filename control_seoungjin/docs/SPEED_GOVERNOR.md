# 외란 연동 속도 조속기 (disturbance-scheduled speed governor)

> 착수 2026-08-22. 사용자 설계: **외란 크기에 따라 순항 속도를 dynamic 하게 포기**한다.
> 경로 기하는 손대지 않고 **참조 궤적을 읽는 가상 시계의 속도**만 조절한다.
> 관련: [YAW_DISTURBANCE_I.md](YAW_DISTURBANCE_I.md) (같은 `ρ` 신호를 공유)

---

## 1. 기구 — "dt 를 키운다"의 정확한 의미

제어기 샘플 주기가 아니라 **참조 시계**를 늦춘다. 샘플 주기를 늘리면 루프 대역폭이 같이 줄어 역효과다.

```
가상 시계 :  τ̇ = s(t),      0 ≤ s ≤ 1
참조 출력 :  p_ref = p(τ),   yaw_ref = ψ(τ)
```

`s ≡ 1` 이면 `τ = t` 라 **기존 동작과 항등**. `s = 0` 이면 시계가 멈춰 제자리 호버.
정지·보류가 별도 상태가 아니라 같은 법칙의 끝점이라 상태기계가 늘지 않는다.

구현: 궤적 Lookup Table 의 시간 입력을 `Clock` → `∫s dt` (Integrator) 로 교체하는 메모리 수술 1건.
(`qc_yawdist_apply` 와 같은 규약: `save_system` 금지, `s≡1` 항등.)

> ⚠ `완화 계약 v0.2` 의 "재시간화" 는 **비행 전 오프라인 재생성**이라 별개 물건이다.
> 여기는 **온라인 시계 조절**이고, 궤적을 갈아끼우지 않으므로 위치·속도 점프가 없다.

## 2. 왜 효과가 있는가 — 미분 차수별 스케일

| 양 | 스케일 | s=0.5 |
|---|---|---|
| 속도 | ∝ s | ×0.50 |
| **가속도** | **∝ s²** | **×0.25** |
| 저크 | ∝ s³ | ×0.125 |
| 스냅 | ∝ s⁴ | ×0.0625 |

수평 가속 = `g·sinθ` 이므로 가속 요구가 1/4 이면 **자세 채널 권한이 그만큼 통째로 남는다.**
그 여유가 외란 상쇄로 간다. 실측(§5): 0.10 N·m 돌풍에서 감속 ×0.5 가 횡이탈 **-75 %**.

## 3. 측정량 — yaw 권한 점유율 ρ

외란 토크를 직접 잴 수 없지만, **정상상태에서 PID 적분기는 "외란을 상쇄하는 데 필요한 명령"을 들고 있다.**
따라서 yaw PID 출력이 그대로 외란 추정치다. 새 센서가 필요 없다.

```
ρ = |u_yaw| / limit_yaw   ∈ [0,1]
```

`diagnose_yaw_final.m` 이 이미 `authSS`/`authPk` 라는 이름으로 계산하는 값이다.
물리 단위 환산: **`τ_max ≈ 0.317 N·m`** (§4) → `ρ = 0.315` ↔ `0.10 N·m`.

## 4. yaw 권한 τ_max 산출 (2026-08-22)

```
호버 로터 속도  n0 = 56.5 + 44.4·m_pkg = 100.9 rev/s   (parameters.m 추력 바이어스)
limit_yaw = 20 전개 →  n = 80.9 / 120.9 rev/s
로터당 반토크  Q = cq·ρ_air·n²·D⁵        (plant_sim.py 상수, 골든 대조본)
τ_max = 2·[Q(120.9) − Q(80.9)] ≈ 0.317 N·m
```

| 외란 | ρ | 비고 |
|---|---|---|
| 0.01 N·m | 3.2 % | 검증 ① (지속) — 적분 배율이 잘 듣는 영역 |
| 0.10 N·m | 31.5 % | 검증 ④ — 3 s 돌풍이면 이미 yaw 279° 이탈 |
| 0.30 N·m | 94.6 % | 검증 ③ — 출력 완전 포화, 어떤 게인도 무효 |

> 부수 확인: C++ `mixYaw = {-1,+1,-1,+1}` 표대로 계산하면 반토크가 상쇄되어 τ_max = **0** 이 나온다.
> yaw 열을 `±SPIN_DIR = {+1,-1,-1,+1}` 로 놓아야 0.317 N·m 가 나오고, 그래야 0.3 N·m 포화 실측과 맞는다.

## 5. 조속 법칙 — 권한 예산 재배분

### 5.0 무엇을 하는 장치인가 (사용자 정의)

**이동 중 외란이 걸리면, 스스로 스펙을 낮춰 성능의 일부를 회복에 돌린다.**

"감속"은 수단이고, 본질은 **권한 예산의 재배분**이다. 네 모터가 base·pitch·roll·yaw 를
한 덩어리로 합산하므로 권한은 **공유 자원**이다. `diagnose_yaw_final.m` 이 이미
`yaw 점유율 > 80 % → roll/pitch 헤드룸 침해, 탈락 후보` 로 경고하는 그 예산이다.

```
평시   :  권한 = 호버 + [추종에 대부분] + [회복 여유 조금]
외란 중:  권한 = 호버 + [추종 축소]     + [회복에 대부분]     ← 재배분
```

추종 몫을 줄이는 손잡이가 가상 시계 `s` 다 — **가속 요구 ∝ s²** 라 지렛대가 크다.

### 5.1 예산식에서 s 를 유도한다

임의의 매핑을 쓰는 대신, **필요한 회복 여유에서 s 를 역산**한다.

| 기호 | 뜻 |
|---|---|
| `a_max` | 자세 채널 권한 전량일 때 낼 수 있는 수평 가속 [m/s²] (**실측 필요**) |
| `a_nom` | 현 궤적이 `s=1` 에서 요구하는 최대 가속 (계획 단계에서 이미 안다) |
| `ρ` | yaw 채널이 외란 상쇄에 쓰고 있는 권한 비율 (§3) |
| `κ` | 회복용으로 남길 몫 (0<κ<1). `κ=0.5` = 남은 권한의 절반을 회복에 |

```
추종이 써도 되는 가속  :  a_req(s) = a_nom · s²  ≤  κ · (1 − ρ) · a_max
                    →     s  ≤  sqrt( κ · (1 − ρ) · a_max / a_nom )
```

- `ρ = 0`, 궤적이 여유 있으면 우변 > 1 → `s = 1` (평시 무개입, **항등**)
- `ρ` 가 커질수록 `s` 가 `sqrt(1−ρ)` 로 떨어진다 — **외란 크기에 맞춰 자동으로 스펙을 포기**
- `ρ → 1` (권한 포화) → `s → 0` = 제자리 정지. 별도 상태기계 없이 끝점이 곧 보류

즉 `ρ_free`/`ρ_stop` 같은 임의 문턱이 필요 없다. 문턱은 `κ` 와 `a_max/a_nom` 이 만들고,
둘 다 물리적으로 의미가 있는 양이다.

### 5.2 회복까지 유지 — ρ 대신 "회복 지표"를 넣는다

#### 왜 ρ 하나로는 안 되는가

`s = f(ρ)` 만 쓰면 **돌풍이 끝나는 순간 ρ 가 떨어져 속도가 복원된다.**
그런데 그 시점의 기체는 yaw 가 100° 틀어진 채 회복 중이다 — §4의 안정성 경계(±90°) 한복판이라
**가장 빨라지면 안 되는 순간에 빨라진다.** 외란 유무가 아니라 **기체가 회복됐는가**로 풀어야 한다.

그래서 입력을 둘로 나눈다.

| 입력 | 무엇을 말하는가 | 언제 큰가 |
|---|---|---|
| `ρ = \|u_yaw\|/limit_yaw` | **외란이 걸리고 있다** | 인가 중에만 |
| `\|e_ψ\|` (yaw 오차, ±180 랩) | **지금 움직이면 위험하다** | 인가 중 **+ 회복 끝날 때까지** |

`e_ψ` 는 돌풍이 끝나도 회복이 완료될 때까지 계속 크다. 즉 **"회복까지 spec 낮춤"이
별도 타이머 없이 이 항 하나로 자동으로 성립한다.** 그리고 이 항은 §4의 90° 안정성 조건을
직접 강제하는 항이기도 하다 — 조속기가 정확도 수단에서 **안정성 수단**으로 승격된다.

그래서 §5.1 예산식의 `ρ` 자리에 **"회복 부담"** 을 넣는다. 둘 중 나쁜 쪽이 지배한다.

```
ρ̄   = LPF(ρ,   τ_ρ)
ē_ψ = LPF(e_ψ, τ_ψ)
ρ_eff = max( ρ̄ ,  |ē_ψ| / ψ_stop )        # yaw 오차도 '권한을 예약한 것'으로 환산
                                            # ψ_stop = 45도 (안정성 경계 90도의 절반)

s*  = min( 1,  sqrt( κ·(1 − clamp(ρ_eff,0,1))·a_max / a_nom ) )
s   = 3차 임계감쇠 필터(s*),  ω_s 방향별 비대칭   # 감속 빠르게 / 복귀 느리게
```

`sqrt(1−·)` 자체가 `ρ_eff → 1` 에서 도함수가 발산하므로, `ρ_eff` 를 smootherstep 으로
한 번 눌러 통과시키거나 `s*` 에 하한 `s_min` 을 두어 C² 를 유지한다 (§6 이 요구하는 조건).

`e_ψ` 는 돌풍이 끝나도 회복이 끝날 때까지 크므로, **"회복까지 스펙 낮춤"이 별도 타이머 없이
이 항 하나로 성립**한다. 동시에 §4 의 90° 안정성 조건을 직접 강제한다 —
조속기가 정확도 수단에서 **안정성 수단**으로 승격되는 지점이다.

- **꺾임 제거**: 단순 `clamp` 는 코너에서 도함수가 튀어 감속 진입·복귀마다 저크가 터진다.
  smoothstep(3차)은 C¹ 까지만이라 **스냅을 보려면 smootherstep(5차)** 이 필요하다.
- **필터 차수**: §6 참조 — 스냅 연속성이 `s⃛` 을 요구하므로 2차로는 부족하다.

### 5.2 복귀 래치 (dwell)

필터의 비대칭 `ω_s` 만으로는 "회복 판정"이 암묵적이다. 명시적으로 건다:

```
s < 1 로 한 번 내려가면  →  u_ρ < ε  AND  u_ψ < ε  가 T_hold 동안 연속 유지될 때만 해제
```

`T_hold ≈ 2 s` 잠정. 해제 후에도 복귀는 느린 `ω_s` 로 올라가므로, 실제 순항 복원까지는
회복 완료 + 2 s + 상승 시간이 걸린다. **서두를 이유가 없다** — 임무에 데드라인이 없다.

### 5.3 왜 시계를 멈추면 발산이 멎는가

§4 의 발산은 **부호가 뒤집힌 위치 피드백이 위치 오차를 증폭**해서 생긴다.
증폭할 오차가 없으면 발산도 없다. 시계를 멈추면 참조가 제자리에 고정되므로 위치 오차가
작게 유지되고, 부호가 뒤집혀 있어도 키울 거리가 없다.

실측이 이 방향을 지지한다 — 같은 0.10 N·m 에서 **느릴수록 이탈이 작다**:

| 케이스 | yaw 잔차 | 횡이탈 |
|---|---|---|
| m010_fast_base (8 s) | −103.7° | 2860 cm |
| m010_slow_base (16 s) | −182.9° (더 나쁨) | **716 cm** |

`slow_base` 는 yaw 가 더 크게 틀어졌는데도 이탈이 1/4 이다. `s → s_min → 0` 으로 밀면
이 추세의 연장선에서 발산이 멎는다는 것이 조속기의 근거다.
(**미검증 — §8 남은 일 4번에서 실측할 것.** 현재는 추세 외삽이다.)

## 6. 스냅까지 고려한 감속 한계 ★

`τ̇ = s` 를 대입해 참조를 시간으로 미분하면 (`p'` 는 τ 미분):

```
ṗ    = p'·s
p̈    = p''·s²  + p'·ṡ
p⃛    = p'''·s³ + 3p''·s·ṡ + p'·s̈
p⁗   = p''''·s⁴ + 6p'''·s²·ṡ + 3p''·ṡ² + 4p''·s·s̈ + p'·s⃛
```

스냅에 **`p'·s⃛`** 항이 있다 → **스냅이 연속이려면 `s` 는 C³** 이어야 하고,
스냅이 유계이려면 최소한 `s ∈ C²` 이고 `s⃛` 이 유계여야 한다.
→ `s*` 는 smootherstep(C²), 필터는 **3차 임계감쇠** 조합이 최소 사양.

### 정량 — 시계가 만드는 항이 경로 자체 한계를 넘지 않을 조건

현 시험 궤적 `p(τ) = 1.5(1 − cos(πτ/T))`, 3 m:

| T | v | a | j | snap |
|---|---|---|---|---|
| 8 s | 0.589 m/s | 0.231 m/s² | 0.0908 m/s³ | 0.0357 m/s⁴ |
| 16 s | 0.295 m/s | 0.058 m/s² | 0.0114 m/s³ | 0.0022 m/s⁴ |

T=8 s 기준, `|p'·(·)| ≤ (경로 자체 한계)` 를 요구하면:

| 조건 | 상한 |
|---|---|
| 가속 항 `p'·ṡ` ≤ a | **\|ṡ\| ≤ 0.393 /s** |
| 저크 항 `p'·s̈` ≤ j | **\|s̈\| ≤ 0.154 /s²** |
| **스냅 항 `p'·s⃛` ≤ snap** | **\|s⃛\| ≤ 0.0606 /s³** |

3차 임계감쇠 필터로 환산하면 (`|s⃛|_peak ≈ ω_s³·Δs`):

| 스냅 예산 | \|s⃛\| 상한 | ω_s | 완전 정지 소요 |
|---|---|---|---|
| 경로 한계의 1배 (엄격) | 0.061 /s³ | **0.39 rad/s** | ≈ 7.6 s |
| 경로 한계의 3배 (여유) | 0.182 /s³ | **0.57 rad/s** | ≈ 5.3 s |

### ★ 결론 — 조속기는 "돌풍"용이 아니다

**스냅을 지키면서 속도를 0 까지 떨구는 데 5~8 초가 걸린다.**
3 초짜리 돌풍은 감속이 끝나기도 전에 지나간다. 즉:

| 외란 성격 | 조속기 유효성 |
|---|---|
| **지속형** (수 초 이상, 정상풍·편심 하중·반토크 불균형) | **유효** — 검증 ① 이 이 영역 |
| **돌발형** (≲3 s 돌풍) | **무효** — 감속이 늦다. 제어기와 yaw 이탈 상한이 담당 |

급감속으로 이걸 이기려 하면 자충수다: `ṡ = −1.0 /s` 로 떨구면 시계가 만드는 감속만
**0.59 m/s² = 순항 가속의 2.5배** 라, 외란 막으려고 스스로 권한을 더 먹는다.

## 7. ρ 의 두 번째 소비처 — 적분 포화 컷오프

같은 `ρ` 를 `YawDistI` 도 소비해야 한다. 실측(§5 m030_fast_g3)에서
**포화 영역(ρ→1)의 적분 배율은 유해**했다 (횡이탈 40.8 cm → 2022 cm).

```
ρ 낮음 :  s = 1,       kiScale = 1 ~ gmax     (외란 흡수 — 적분이 일한다)
ρ 높음 :  s → s_min,   kiScale = 0            (포화 방어 — 적분을 얼린다)
```

오차가 큰 이유가 *외란이 걸려서* 인지 *권한이 바닥나서* 인지를 `ρ` 로 가른다.
현행 `YawDistI` 는 "오차 크면 무조건 강화" 라 포화 영역까지 밀고 들어간다 → **v2 에서 컷오프 추가 필요**.

## 8. 상수 (잠정) 와 남은 일

| 이름 | 잠정값 | 근거 |
|---|---|---|
| `κ` | 0.5 | 남은 권한의 절반을 회복 몫으로 예약 |
| `a_max` | **실측 필요** | 자세 채널 권한 전량의 수평 가속. 스윕으로 측정 (§8-0) |
| `a_nom` | 궤적별 | 계획 단계 산출값 (예: 3 m/8 s 레이즈드 코사인 = 0.231 m/s²) |
| `ψ_stop` | 45° | 안정성 경계 90° 의 절반 — 경계에 닿기 한참 전에 정지 |
| `T_hold` | 2 s | 복귀 래치 dwell |
| `s_min` | 0.2 | 완전 정지 대신 최저 순항 유지 (창문 접근 중 정지 회피) |
| `ω_s` (감속) | 0.5 rad/s | §6 스냅 예산 3배 |
| `ω_s` (복귀) | 0.15 rad/s | 비대칭 — 복귀는 서두를 이유가 없다 |

**남은 일**
0. **`a_max` 실측** — 조속기 꺼둔 상태에서 순항 가속을 올려가며 자세 채널이 포화하는 지점.
   예산식의 유일한 미지수다
1. Simulink 가상 시계 수술 `qc_clock_gov_apply.m` (`s≡1` 항등 회귀 필수)
2. `ρ` · `e_ψ` 산출·로깅 (`Control Yaw` 출력 탭 / `Add3` 출력 탭 → `To Workspace`)
3. `YawDistI` v2 포화 컷오프
4. **조속기 켜고 `verify_yawdist_move` 재실행** — 핵심 검증: 0.10 N·m 에서 28 m 발산이
   실제로 멎는가 (§5.3 은 아직 추세 외삽). 멎으면 조속기가 안정성 수단으로 확정,
   안 멎으면 yaw 루프 대역폭 자체를 손봐야 한다
5. `ψ_free` 와 scan 슬루의 충돌 정리 — 슬루 중엔 추종 지연만으로 32.8° 가 나오므로
   `e_ψ` 대신 `e_ψ − (예측 지연)` 을 쓰거나 슬루 게이트를 공유해야 한다
6. C++ 동기 + 골든 재대조

## 9. 연산 지연을 덮는 파이프 (2-rate 구조)

외란 대응이 "재계획"을 거치면 수백 ms~초의 연산 지연이 생긴다. **그 사이에도 기체는 날고
있으므로 먹일 참조가 끊기면 안 된다.** 그래서 계층을 나누고, 맨 아래 층이 지연 없이
혼자 굴러가게 만든다.

| 층 | 주기 | 하는 일 | 지연 |
|---|---|---|---|
| **L0 가상 시계 조속기** | **제어 주기 (매 스텝)** | `ρ`·`e_ψ` 읽고 `s` 갱신, `τ += s·dt`, 참조 조회 | **0 — 산술 수십 flop** |
| L1 감독자 | ~10 Hz | 모드 판정, 재계획 요청, 우선순위 중재 | ms급 |
| L2 계획기 | 이벤트/수백 ms~초 | 새 궤적·스플라이스 산출 | **여기가 느린 곳** |

### L0 가 곧 "파이프"다

가상 시계 방식을 고른 결정적 이유가 이것이다. L0 는 **기존 궤적만으로 무한히 굴러갈 수 있다** —
새 계획도, 외부 입력도 필요 없다. 게다가 `s ≤ 1` 은 요구 속도·가속·저크·스냅을 **전부 축소**하는
방향이라, 원래 궤적이 실현 가능했다면 감속판도 반드시 실현 가능하다.
**구조적으로 안전한 폴백**이라 별도 검증이 필요 없다.

> 오프라인 재시간화(완화 계약 v0.2)로 같은 일을 하려면 L2 를 거쳐야 하고, 그 지연 동안
> 먹일 참조가 없다. 이게 온라인 시계 조절을 택한 이유다.

### 이어붙이기 (L2 결과 도착 시)

L2 가 새 궤적을 내놓으면 splice 계약(INTERFACE_SPEC)으로 이어붙인다. 이때 **L0 의 `τ`·`s`
상태를 인계**해야 위치·속도가 튀지 않는다. 새 궤적은 현재 `τ` 지점의 상태(위치/속도/가속)를
초기 조건으로 받는다.

### 실패 안전

L1/L2 가 죽으면 (하트비트 stale — `flight_supervisor.heartbeat_stale()`, 철칙 3)
L0 는 `s → 0` 으로 내려가 제자리 호버로 수렴한다. 상위가 없어도 **가만히 멈추는 것**이
기본 동작이라 폭주하지 않는다.

### 계산량

L0 한 스텝: LPF 2개, clamp·sqrt·smootherstep 각 1회, 3차 필터 1개, 적분 1개.
**부동소수 수십 회** — 1 kHz 루프에 넣어도 무시할 수준이고, 임베디드 강등에도 문제없다
(qc_controller.hpp 설계 규약: 힙 할당·예외·가상함수 없음).

## 10. 성형기 재실행 지연과 비상 계획 (2026-08-22 실측)

사용자 요구: 외란 → **낮춘 spec 으로 성형기 재실행** → 회복되면 **정상 spec 으로 다시 성형해
남은 경로 완주**. 문제는 **그 성형이 도는 동안 날릴 계획이 따로 필요**하다는 것.

### 10.1 실측 지연 (이 개발 머신, Python)

| 남은 경로 | N | `traj_smoother` | `traj_zv(zvd)` | `traj_gate` | 합 |
|---|---|---|---|---|---|
| 5 s @ dt=0.01 | 501 | 17.6 ms | 0.04 | 0.22 | **17.8 ms** |
| 10 s @ dt=0.01 | 1001 | 43.2 ms | 0.09 | 0.34 | **43.6 ms** |
| 20 s @ dt=0.01 | 2001 | 80.2 ms | 0.10 | 0.54 | **80.8 ms** |
| 10 s @ dt=0.002 | 5001 | 154.7 ms | 0.12 | 0.54 | **155.4 ms** |

**병목은 `traj_smoother` 단독** (ZVD·게이트는 1 ms 미만). 남은 경로 길이에 비례한다.

```
build_emergency_stop  :  0.31 ms      <- 성형기의 1/140 ~ 1/500. 닫힌형 2단 정지식
```

여기에 감독자 틱(~10 Hz = 최대 100 ms)과 `current_state` 30 Hz 신선도(최대 33 ms)를 더하면
**종단 지연 예산은 대략 100~300 ms**. 순항 0.59 m/s 에서 300 ms = **18 cm 이동** —
창문 통과 여유가 cm 급인 것을 감안하면 무시할 수 없다.

### 10.2 규칙 — 중단 지선 없는 계획은 실행하지 않는다

재귀적 실현가능성(recursive feasibility). **어느 순간에든 즉시 갈아탈 수 있는
유효한 정지 궤적을 항상 손에 들고 있어야** 성형기 지연을 안전하게 덮을 수 있다.

| 차선 | 무엇 | 지연 | 언제 |
|---|---|---|---|
| **A 공칭** | 현재 성형본 | — | 평시 |
| **L0 가상 시계** | `s` 감속 (§1) | **0** | 1차 파이프 — 부드럽게 스펙 낮춤 |
| **B 비상 지선** | `build_emergency_stop(현재 상태)` | **0.31 ms** | 2차(최후) 파이프 — 권한 초과·발산 위험 |
| **C 재성형본** | 낮춘/정상 spec 재성형 | 18~155 ms | 준비되면 splice 로 이어붙임 |

- L0 는 지연 0 이고 **원 궤적이 실현 가능했으면 감속판도 반드시 실현 가능**하므로 검증이 필요 없다
- B 는 `gate_ok` 를 반환값에 이미 담고 있다 (`build_emergency_stop` 이 게이트를 통과시킴)
- C 도착 시 `replan_splice(res1, tau_s, new_waypoints, cfg)` 로 현재 상태에서 이어붙인다

### 10.3 지연을 아예 없애는 방법 두 가지

**(a) 리시딩 호라이즌 — 지연 상한을 고정**
남은 경로 전체가 아니라 **앞으로 5 초분만** 재성형한다. 위 표에서 5 s = 17.8 ms 로 고정되어,
경로가 아무리 길어도 지연이 커지지 않는다. 5 초 뒤 구간은 다음 주기에 성형.

**(b) 스펙 사다리 사전 성형 — 지연을 0 으로**
spec 배율을 미리 몇 칸으로 정해 두고 (`×1.0 / ×0.7 / ×0.5 / ×0.3`),
**계획 시점에 네 벌을 다 성형해 둔다.** 외란이 오면 계산 없이 해당 칸으로 갈아타면 된다.
- 비용: 계획 시 성형기 4회 (수백 ms, 비행 전이라 무관) + 궤적 4벌 메모리
- 칸 사이의 연속적인 보간은 L0 가상 시계가 담당 → 사다리가 성글어도 부드럽다
- **이 조합이면 비행 중 성형기 재실행이 아예 필요 없다** — C 차선이 사라진다

권장: **(b) 를 기본, (a) 를 사다리 밖 상황(경로 자체가 바뀌는 재계획)의 안전장치로.**

### 10.4 전체 시퀀스

```
평시        : A 실행,  B 를 매 틱 갱신(0.31 ms),  s = 1
외란 감지   : (즉시) L0 가 s 를 §5 예산식대로 낮춤        <- 지연 0, 파이프 시작
              동시에 사다리에서 해당 칸 선택 (b) 또는 C 요청 (a)
권한 초과   : B 로 전환 — 저크 제한 최단 정지            <- 최후 파이프
새 계획 도착: 현재 상태에서 splice, s 는 인계
회복 판정   : rho_eff 하락 + T_hold -> 상위 칸으로 복귀, s -> 1 (느린 omega_s)
              남은 경로 완주
```

## 11. 사다리 승강 규칙 — 외란을 모델링하지 않는다 (사용자 설계)

외란이 일정하다는 보장이 없으므로 **외란을 추정해서 s 를 계산하지 않는다.**
대신 **결과를 보고 칸을 오르내린다.**

| 방향 | 무엇을 보고 | 뜻 |
|---|---|---|
| **내림** | 오차가 문턱을 넘음 | 외란이 커졌다 |
| **올림** | 남은 여유 spec 이 문턱을 넘음 | **spec 을 낭비하고 있다** |

이건 §5 의 예산식을 폐기하는 게 아니라 **초기 칸 간격을 정하는 데만 쓰고, 운용은 관측으로**
한다는 뜻이다. 덕분에 `a_max` 실측이 필수가 아니라 권장으로 내려간다 (사다리가 스스로 찾는다).

### 11.1 선행 지표와 후행 지표를 같이 본다

```
rho    = max( |u_yaw|/limit_yaw ,  |u_att|/limit_att )   # 선행 — 제어기가 '이미 싸우는 중'
e_norm = max( |e_track|/e_budget ,  |e_psi|/psi_stop )   # 후행 — '이미 졌다'
m      = 1 - rho                                          # 남은 여유 spec
```

`e` 만 보면 **오차가 생긴 뒤에야** 반응한다. `rho` 는 오차가 커지기 전에 먼저 오른다 —
제어기가 외란과 싸우기 시작한 순간 권한 점유가 올라가기 때문이다.
**내림은 rho 가 먼저 걸리게, e 는 백스톱으로.**

### 11.2 승강 규칙 (AIMD 형)

판정 주기 `T_dec ~ 0.5 s`, 칸 = `{x1.0, x0.7, x0.5, x0.3}` (잠정):

```
if   e_norm > 1.0                          ->  두 칸 내림 (또는 B 비상 지선)
elif rho > RHO_DOWN (0.6)  or  e_norm > E_DOWN (0.6)   ->  한 칸 내림
elif m > M_UP (0.5)  and  e_norm < E_UP (0.3)
     가 T_hold (2 s) 동안 연속 유지        ->  한 칸 올림
else                                       ->  유지
```

- **급격한 내림 / 한 칸씩 느린 올림** = AIMD. 미지의 시변 외란에 대해 검증된 형태다
  (혼잡 제어와 같은 이유 — 외란 모델 없이 안전측으로 수렴한다)
- **히스테리시스**: 내림 문턱 0.6 vs 올림 문턱 0.3 사이의 갭이 칸 진동을 막는다
- **dwell**: 올림에만 `T_hold` — 내림은 즉시 (안전이 급하다)
- 칸 사이 전환은 **L0 가상 시계가 연속 보간** (smootherstep + 3차 필터, §5.2/§6)
  → 사다리가 이산이어도 참조는 C³ 를 유지한다

### 11.3 왜 "여유를 보고 올린다"가 옳은가

`rho` 가 낮다는 것은 **제어기가 놀고 있다**는 뜻이고, 그 상태로 느리게 가는 건 순수한 손해다.
반대로 외란이 사라졌는지를 직접 판정할 방법은 없다 — 외란은 관측되지 않는다.
**"쓸 수 있는데 안 쓰고 있다"** 는 관측 가능하고, 그게 복귀 신호로 충분하다.

`e_norm < E_UP` 조건을 AND 로 붙이는 이유: 여유가 있어도 아직 오차가 남아 있으면
(= 회복 중이면) 올리면 안 된다. §5.2 의 "회복까지 유지"가 여기서도 그대로 성립한다.

## 12. 1차 구현·검증 결과 (2026-08-22)

### 12.1 구현물

| 파일 | 내용 |

**정찰 결과 — 수술점이 한 곳이다:**
```
Reference/Clock1 (Clock) --> Reference/Interpolate Spline Points
                               +- Min(t, timespot_spl(end)) --> Lookup x4
                                  (spline_yaw, spline_data 1/2/3)
```
궤적 변수를 쓰는 블록 5개가 전부 같은 `Min` 하나에서 시간을 받고, 그 `Min` 은 `Clock1` 하나에서 온다.

**구현 중 걸린 것 2건**
- **필터 초기조건**: `s` 를 직접 3차 필터에 넣으면 TransferFcn IC=0 이라 `s(0)=0` — 시작부터 시계가 멎는다.
  → "1 로부터의 편차 `d`" 를 필터하고 `s = 1 − gov_on·d` 로 뺐다. IC 0 이 곧 `s(0)=1`.
- **Fcn 블록 min/max 미지원** → `sat01(x) = (|x|−|x−1|+1)/2` (qc_nl_att_apply 와 같은 교훈)

### 12.2 기구는 설계대로 동작한다

0.10 N·m x 3s 돌풍, `gov_on=1`:

| t [s] | 8.0 | 9.0 | 11.0 | 15.0 | 25.0 |
|---|---|---|---|---|---|
| `s` | 1.0000 | 0.9970 | 0.8850 | 0.4870 | 0.2087 |
| `τ` | 8.00 | 9.00 | 10.91 | 13.63 | 16.49 |

무개입 → 매끄러운 감속 → `s_min` 근처 유지 (`e_ψ` 가 커서 복귀 안 함 = §5.2 설계대로).
`τ` 가 실제 시간보다 **8.5 s 뒤처짐** = 임무가 그만큼 늦어짐.

### 12.3 ★ 그러나 발산은 멎지 않는다 — §5.3 의 추론이 틀렸다

| 케이스 | x_end | y_end | 목표 |
|---|---|---|---|
| base | **29.19 m** | 27.46 m | (3, 0, 1) |
| gov_off | 2.98 m | **−11.08 m** | 〃 |
| gov_on | **13.10 m** | −0.07 m | 〃 |

`gov_on` 도 x 축으로 13 m 날아갔다. **§5.3 "시계를 멈추면 증폭할 오차가 없다" 는 오류다** —
yaw 가 뒤집히는 시점에 **이미 존재하는 위치 오차**가 있고, 부호가 뒤집힌 루프는 그걸 증폭한다.
감속은 오차 *증가율* 만 줄일 뿐 양의 피드백 자체를 없애지 못한다.

> ⚠ 초판 판정 로직이 **횡방향 `y` 만** 재서 `gov_on` 의 18.2 cm 를 "발산 멎음" 으로 오출력했다.
> x 로 13 m 날아간 것을 놓쳤다. 지표를 3D 로 고쳤다. **축이 바뀌면 눈이 머는 지표를 쓰면 안 된다.**

### 12.4 항등 회귀는 조건이 틀렸다

`gov_off` 에서 `s_min = 1.0000` (시계는 정확히 `τ=t`) 인데 base 와 38.78 m 차이가 났다.
**발산 구간에서 항등을 재는 것이 무의미**하기 때문이다 — Integrator 가 연속 상태를 하나 추가해
가변스텝 솔버의 스텝 배열이 바뀌고, 불안정 루프가 그 1e-9 급 차이를 수십 m 로 증폭한다.
→ **외란 0 조건에서 재측정** (`verify_clock_gov.m` A상).

### 12.5 결론 — 순서가 바뀐다

조속기는 **yaw 이탈이 ±90° 안에 묶인다는 전제 위에서만** 의미가 있다.
그 전제가 깨지면 조속기로는 못 막는다. 우선순위:
