# yaw 외란 적응 적분 (dynamic Ki) — 설계·검증 계획

> 착수 2026-08-22. 지도교수 피드백 "외란에 더 강인하게" 에 대한 yaw 채널 대응.
> 사용자 설계 원안: **외란이 감지되면 I 값을 한시적으로 조정**한다.

---

## 1. 왜 yaw 인가 / 왜 I 인가

yaw 는 반토크로만 움직이는 **약권한 채널**이다. 12차 재튜닝 기록(`parameters.m` 주석)에 그대로 남아 있다.

- PD 만으로는 지속 외란에서 **42~65° 영구 고착** → 적분 없이는 소거 자체가 불가능
- 그래서 `ki_yaw = 1.5` (Ti = 10 s) 를 상시 켜 둔다
- 그런데 이 값은 "평시 지터를 안 건드리는 선"에서 고른 것이라 **외란 소거가 느리다**

즉 현행 Ki 는 *평시 기준*으로 정해져 있고, 외란 구간에서는 과소하다. 상수 Ki 를 올리면 평시 지터·오버슈트가 나빠진다(12차에서 이미 확인된 맞교환). → **구간별로 다른 Ki** 가 정확히 이 맞교환을 푸는 수단이다.

## 2. 무엇을 조정하는가 — Ki 가 아니라 "적분 누적률"

```
integ += ki * kiScale * e * dt
```

`ki` 자체를 바꾸면 **이미 쌓인 적분값이 통째로 재스케일**되어 출력에 계단 점프가 생긴다.
여기서는 누적 *속도*만 곱한다. 배율이 1→3 으로 뛰어도 그 순간 출력은 연속이고,
이후 오차 소거가 3배 빨라질 뿐이다. 해제 시에도 마찬가지 — **쌓인 적분값은 유지된다**
(그게 곧 외란 토크의 추정치이므로 버리면 안 된다).

## 3. 외란을 어떻게 "감지"하는가 (핵심 설계 판단)

`|e|` 만 보면 안 된다. **scan 미션은 yaw 를 0.6~1.0 rad/s 로 의도적으로 슬루**한다
(`3267d34` 스캔 속도 조율: 시뮬 1.0 / 실기 0.6). 슬루 중의 추종 오차는 외란이 아니다.
`|e|` 기반으로 적분을 키우면 **슬루마다 오버슈트를 만든다** — 즉 강건성을 올리려다 임무를 깬다.

두 겹으로 거른다.

| 겹 | 식 | 거르는 것 |
|---|---|---|
| (a) 지속성 | `ē = LPF(e, tau=1.0s)` | 순간 오차·노이즈 (외란은 "남아 있는" 오차) |
| (b) 명령 게이트 | `|ψ̇_ref| > rateGate` 면 판정 자체를 안 함 | 의도된 슬루 구간 |

감지 강도:

```
k = sat01( (|ē| - e0) / e1 )          # e0=2°, e1=2° → 2°에서 시작, 4°에서 포화
g = 1 + (gmax - 1) * k                # Pid::kiScale 에 물림
```

상승은 **즉시**(외란 대응은 빨라야 한다), 하강은 `relax = 0.5 /s` 로 완만히
(문턱 경계에서 채터링하면 적분률이 요동친다).

## 6. 검증 결과 (2026-08-22, MATLAB R2026a)

구성: 25 s 제자리 호버, `t = 8 s` 부터 z축 토크 **0.01 N·m 지속 인가**

정상편차 = 마지막 3 s 평균 − 외란 전(4~8 s) 평균.

| 구성 | 정상편차 | base 대비 | 최대이탈 | 평시 호버 지터 | 자세 RMS |
|---|---|---|---|---|---|
| `base` (수술 없음) | **7.676°** | 100 % | 39.37° | 0.0108° | 0.002° |
| `g1` (수술, gmax=1) | **7.676°** | 100 % | 39.37° | 0.0108° | 0.002° |
| `g3` (gmax=3) | **0.719°** | **9.4 %** | 35.54° | 0.0108° | 0.002° |
| `g5` (gmax=5) | **0.293°** | **3.8 %** | 33.11° | 0.0108° | 0.002° |

- **항등 회귀 합격**: `g1` vs `base` 전 구간 최대 yaw 차 **0.00000°**.
  외부 P/I/D/N 포트 배선이 내부 파라미터 모드를 정확히 재현한다 (포트 순서 e,P,I,D,N 도 이로써 실증).
- **정상편차 소거**: gmax=3 에서 7.68° → 0.72° (**-90.6 %**), gmax=5 에서 0.29° (**-96.2 %**).
- **평시 지터 무열화**: 0.0108° 로 세 구성 모두 **완전 동일** — 게이트가 외란 전 구간에서 열리지 않았다는 뜻.
  상수 Ki 를 올렸을 때의 맞교환(12차에서 확인된 것)이 여기서는 발생하지 않는다.
- 최대이탈은 39.4° → 33.1° 로 개선폭이 작다. 당연하다 — **과도 초기는 P/D 의 몫**이고
  적분은 정상편차를 지우는 항이다. 이탈 크기까지 줄이려면 별도 수단(자세 채널의 `qc_nl_att_apply`
  같은 오차 의존 비선형 게인)이 필요하다.

### ② scan 슬루 반증 시험 — `diagnose/verify_yawdist_slew.m`

구성: 외란 없음. yaw 참조를 `t = 3~11 s` 동안 **0.6 rad/s (실기 scan 속도)** 로 램프 = 총 275°.

| 구성 | 슬루 중 최대 추종오차 | 슬루 중 g1 대비 최대차 | 개입 시작 | t=15 s 오차 | t=20 s 오차 |
|---|---|---|---|---|---|
| `g1` | 32.797° | — | — | 24.18° | 12.08° |
| `g3` | 32.797° | **0.00000°** | t=11.58 s (슬루 종료 +0.58 s) | 17.15° | **4.76°** |
| `g5` | 32.797° | **0.00032°** | t=11.43 s (슬루 종료 +0.43 s) | 10.89° | 5.76° |

- **합격**: 슬루 구간 안에서 세 구성이 사실상 완전히 같다. 명령 게이트가 설계대로 닫힌다.
- 개입은 슬루가 **끝난 뒤 0.4~0.6 s** 부터 시작된다. `yd_taud=0.02` 미분 필터 +

  **의도한 동작**: 슬루가 끝나면 남은 오차는 "지속 오차"이므로 게이트가 열리는 게 맞다.

> ⚠ 초판 판정 로직은 비교 창을 **전 구간(0~20 s)** 으로 잡아 이 정상 동작을 "불합격"으로
> 출력했다 (`g3 vs g1 13.08°`). 판정 창을 슬루 구간으로 한정하도록 스크립트를 고쳤다.
> 원 로그를 볼 때 주의할 것.

### ③ 부수 발견 — yaw 슬루 추종 자체가 나쁘다 (본 기능과 무관)

0.6 rad/s (= 34.4 °/s) 슬루에서 **추종 지연 32.8°** (≈ 0.95 s 분), 슬루 종료 후
**오버슈트 27~29°**, 20 s 시점에도 잔차가 남는다. yaw 가 약권한 채널이라는 것의 직접적 증거다.
scan 미션 설계(`3267d34`: 시뮬 1.0 / 실기 0.6 rad/s)가 이 지연을 전제하고 있는지 확인이 필요하다.
**적분 배율로는 못 고친다 — 슬루 추종은 P/D 와 권한의 문제다.**

## 7. 열린 항목

- **`mixYaw` 부호 재확인 필요**: `qc_controller.hpp` 의 `mixYaw = {-1,+1,-1,+1}` 과
  `mixDir = {+1,-1,-1,+1}`(= 실측 회전방향) 을 같이 놓고 반토크를 계산하면
  `τ_yaw ∝ -Σ(base + mixYaw_i·u)²` 이고 `Σ mixYaw_i = 0` 이라 **1차항이 상쇄**된다.
  DYNAMICS.md 의 골든 트레이스 확정(2026-08-18)은 x/y 런의 **roll/pitch** 상관으로 한 것이라
  yaw 열은 같은 방식으로 검정되지 않았다. yaw 실비행 1편(대기/예약 큐)에서 함께 판정할 것.
  — 이 항목은 본 기능과 독립이지만, **yaw 권한 실측 없이는 gmax 스윕 해석이 흔들린다**.
- ~~Simulink 측 구현 방식 결정~~ → **경로 A 확정** (`diagnose/probe_yaw_pid.m` 정찰, 2026-08-22).
  `Control Yaw` = `PID 1dof` 마스크, **Parallel / Forward Euler / AntiWindup none / LimitOutput on**
  으로 C++ `Pid` 와 구조가 정확히 같다. `ControllerParametersSource='external'` 전환이 되고
  Inport 가 1개 → 5개(e, P, I, D, N)로 늘어난다. I 포트만 시변으로 물리고 P/D/N 은 마스크 변수
  (`yaw_kp`/`yaw_kd`/`yaw_f`)를 상수로 되먹인다.

## ⑤ 정정 — 발산의 진범은 짐 투하였다 (2026-08-22 후반)

`verify_yaw_robust.m` 에 **투하 로직 무력화**를 넣고 같은 조건(0.10 N·m x 3 s, 3 m/8 s 이동)을
다시 돌린 결과:

| 케이스 | 경로이탈 | 종점오차 | yaw 끝 |
|---|---|---|---|
| base | 5.0 cm | **0.0 cm** | −55.2° |
| wrap (±pi 랩) | 5.0 cm | **0.0 cm** | **−0.1°** |
| aw (anti-windup) | 5.0 cm | **0.0 cm** | **−3.2°** |
| wrap + aw | 5.0 cm | **0.0 cm** | 1.3° |
| wrap+aw+조속기 | 5.0 cm | 0.0 cm | 1.3° (s_min 0.4934) |
| 외란 0 + 전부 | 5.0 cm | 0.0 cm | 0.0° (s_min **0.9998**) |
| p30_base (0.30 N·m) | 5.0 cm | 0.0 cm | **103.6°** |

**1 kg 에서는 위치가 아예 흔들리지 않는다.** 0.3 N·m 에서도 경로이탈 5 cm / 종점오차 0.
문제는 오직 **남는 기수 오차**다.

### 원인

마지막 웨이포인트 도달 → 투하 로직 발동 → 짐 2.27 → 1.27 kg. 그런데 게인은 1 kg 스케줄
그대로다(**질량 스케줄은 비행 전 1회 계산, 비행 중 재계산 없음**). 자세 게인이 33% 과대해져
투하 후 구간이 불안정해지고, 그 구간에서 솔버 스텝 차이 1e-9 가 수십 m 로 증폭됐다.
yaw 잔차와의 상관은 투하 시점의 기수 방향이 밀림 방향을 갈랐기 때문으로 보인다.

### 교훈 (하네스)

1. **이동 시험은 투하 로직을 반드시 끌 것** — `Disengage Logic/Distance to drop waypoint/Constant* → -1`
2. **판정 지표는 축에 무관해야 한다** — 초판이 횡방향 `y` 만 재서 x 로 13 m 날아간 것을
   "발산 멎음" 으로 오출력했다. 3D → 다시 '직선 경로로부터의 수직 거리' 로 교정
3. **발산 구간에서 항등 회귀를 재지 말 것** — 불안정 루프가 솔버 차이를 증폭한다.
   무외란 조건에서 재면 가상 시계 수술은 t≤13 s 구간 **0.00000 m** 로 정확히 항등이다

### 살아남은 결론

- **yaw ±pi 랩은 실효가 있다**: 돌풍 후 기수가 55.2° 틀어진 채 남던 것이 0.1° 로 회복.
  구운 모델의 `Add3` 에는 랩이 없고 C++ 이식본은 이미 `wrapPi` 를 쓴다 — **둘이 달랐다.**
- **anti-windup(clamping) 도 단독으로 거의 같은 효과** (−3.2°). 랩과 독립적으로 듣는다.
- **조속기는 평시 공짜** (외란 0 에서 s = 0.9998, 손실 0.02%) 지만 1 kg 에서는 고칠 게 없다.
