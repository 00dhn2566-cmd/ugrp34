# 실모델 노이즈 주입 → 3D 복원 오차 역산 (eval 목표치 도출) — 설계

> 2026-08-08 · 담당: 류길남 · 체크리스트 0번 ⓐ안 + 3번 "실모델 출력으로 재검증" 해소용
> 근거 문서: `overall_gilnam/docs/To_do_checklist_gilnam.md`, `overall_gilnam/vision/sample_stream/README_stream.md`, `visual_imaging_taemin/README.md` (7/4 결과표)

## 배경·목적

1차 학습 모델의 corner 픽셀 오차 실측치(2026-08-02 본 판정: **평균 8.87px / p95 36.6px / 미검출 31/802 ≈ 3.9%**)가 가안 목표(평균 ≤3px)를 초과했다. 가안은 "1차 학습 후 조정" 전제였으므로, 임무 요구(창문 0.8~1.2m 통과)에서 **허용 픽셀 오차를 역산해 목표치를 재산정**한다.

방법: GT 스트림에 실측 프로파일 노이즈를 배율별로 주입 → 삼각측량 3D 복원 오차 곡선 산출 → 통과 여유(margin)별 허용 픽셀 오차 역산. 이 과정이 체크리스트 3번 "실모델 출력(노이즈 포함)으로 태민 복원 재검증"과 동일 작업이므로 함께 해소한다.

**제약**: 이 컴퓨터에는 `best.pt`·재생성 데이터셋이 없다(다른 로컬). 따라서 실추론이 아닌 **실측 통계 기반 합성 노이즈**로 진행한다 — 체크리스트 ⓐ안의 정의와 일치.

## 범위

- 새 파일 2개 + 테스트만 추가 (`overall_gilnam/vision/`). 기존 코드 무변경.
- 3D 복원은 태민 코드가 아니라 **README_stream.md 계약 레시피의 재현 구현** — 무노이즈 정합 게이트로 검증 후 사용. 태민 원본 코드와의 교차 확인은 후속(패키지 전달)으로 남긴다.
- margin(기체 유효 크기·제어 추적 오차) 확정은 범위 밖 — 파라미터(5/10/15cm)로 병기하고 회의 안건으로 넘긴다.

## 구성요소

| 파일 | 역할 |
|---|---|
| `vision/noisy_stream.py` | GT 스트림 jsonl → 실측 프로파일 노이즈 주입 jsonl (배율별) + 태민 전달용 ×1.0 패키지 |
| `vision/eval_recon3d.py` | §5+pose 스트림 (1개 이상) → 삼각측량 3D 복원 → `scene_gt.json` 대조 오차표 (markdown) |
| `vision/tests/test_noisy_stream.py` | 캘리브레이션 정합·시드 재현성·§5 스키마 불변·드롭률 |
| `vision/tests/test_eval_recon3d.py` | 무노이즈 mm 정합·배율↑→오차 증가 sanity |

데이터 흐름 (파일로만 통신 — 태민 전달물과 평가 입력이 동일):

```
make_stream.py (기존, seed 42)
  → sample_stream.jsonl + scene_gt.json
noisy_stream.py --scales 0.25,0.5,1,1.5,2,3 --seed 1234
  → noisy_x{scale}.jsonl (6개) + 태민 패키지(×1.0 + README)
eval_recon3d.py --scene-gt scene_gt.json --streams <원본+6개>
  → 스윕 결과표 (무노이즈 행 = 정합 게이트)
```

## 노이즈 모델

- **corner 픽셀 노이즈**: 실측 분포는 가우시안 대비 꼬리가 무거움 (가우시안이면 p95 ≈ 평균×1.96 ≈ 17px인데 실측 36.6px). → **2성분 가우시안 혼합**: 확률 1−p로 코어 N(0, σc²), 확률 p로 꼬리 N(0, σt²) (per-axis, corner별 독립). p = 0.1 고정, (σc, σt)는 2D 반경 오차의 평균 = 8.87px, p95 = 36.6px를 동시에 만족하도록 스크립트 내 수치 탐색(이분법)으로 캘리브레이션 — 결정적 계산.
- **미검출**: 창문×프레임 단위 드롭, 확률 31/802 (≈0.0387).
- **배율**: 캘리브레이션된 (σc, σt)에 공통 배율 {0.25, 0.5, 1, 1.5, 2, 3} 적용. 미검출률은 배율과 무관하게 고정 (미검출은 도메인 문제로 픽셀 정밀도와 별개라는 가정 — 문서 한계에 명시).
- **불변 필드**: det_conf·color_conf·corner_vis·center 재계산 외 §5 구조 유지. center는 노이즈 주입 후 재계산. vis=0 corner에도 노이즈는 적용하되 복원에서 제외되므로 영향 없음.
- **재현성**: `--seed` (기본 1234) 고정 rng.

## 복원 평가 (태민 레시피 재현)

- README_stream.md 계약 그대로: quat(xyzw)→R, P = K·[R_wcᵀ | −R_wcᵀ·t_wc], `cv2.triangulatePoints`.
- intrinsics: `scene_gt.json`의 사본(fx/fy/cx/cy)에서 K 재구성.
- 프레임쌍 선정: 해당 창문의 4 corner 모두 vis=1인 프레임 중 카메라 위치 차 ≥ 0.5m인 모든 쌍. 프레임 수가 크면 쌍 수 상한(예: 창문당 2,000쌍, 균등 서브샘플)으로 계산량 제한 — 상한 적용 여부는 출력에 기록.
- 집계: 쌍별 삼각측량 결과의 **corner별 성분 중앙값** (꼬리 노이즈 강건). 태민의 실제 집계 방식은 미상이므로 "중앙값 집계" 가정을 결과 문서에 명시.
- 지표 (창문 3개 × 배율별): corner 3D 오차(mean/max), 중심 오차, 크기(w×h) 오차. 임무 판단에는 중심·크기 오차가 직결.
- **정합 게이트**: 무노이즈 스트림에서 corner 오차 ≤ 1mm (태민 7/4 표 0.01~0.07mm와 자릿수 정합) 통과 후에만 스윕 결과를 신뢰.

## 성공 기준

1. 무노이즈 정합 게이트 통과 (corner ≤ 1mm).
2. ×1.0 주입 노이즈의 표본 통계가 실측치 정합: 평균·p95 각 ±5% 이내 (대표본 테스트).
3. 배율 스윕 곡선표 + margin 역산표 + 목표치 제안 문서 산출.
4. 신규 테스트 포함 `vision/tests/` 전체 통과.

## 한계·가정 (결과 문서에도 동일 기재)

- 노이즈를 corner별 **iid**로 가정 — 실모델은 프레임 간·corner 간 상관(같은 창문의 corner들이 함께 틀리는 경향)이 있을 수 있어, iid 가정은 다중 쌍 집계에 유리하게(=3D 오차를 과소평가하는 쪽으로) 작용할 수 있음. 목표치 제안 시 이 방향성을 감안해 보수적으로 해석.
- 미검출·p95 꼬리의 원인(거리·각도 의존성)은 미반영 — 실측 거리 구간별 오차가 8.3~10.3px로 비교적 균일해 거리 무관 노이즈로 단순화.
- 삼각측량 집계 방식이 태민 원본과 다를 수 있음 → 패키지 교차검증으로 보완.

## 후속 (범위 밖)

- 회의: margin 확정 → 목표치 확정 → ⓑ(imgsz=960 재학습·미검출 원인 분석) 필요 여부 판단.
